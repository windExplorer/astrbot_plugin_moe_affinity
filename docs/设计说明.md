# 萌萌好感度 · 设计说明

本文件记录已确认的设计口径。改动实现前先读这里；口径变了要同步改这里。

## 1. 定位

全插件共用的好感度中枢：自己算、自己存、自己注入，并向自家其它插件提供版本化读写契约。
不替代任何第三方插件，只做「生态里缺的那一层数值化」。

## 2. 作用域：角色（role），不是人格，也不是群

**结论：好感度按「角色 × 用户」唯一，一个角色对一个人只有一份分数。**

AstrBot 的人格是**按会话（umo）解析**的（`persona_mgr.resolve_selected_persona`）：
优先级 `umo 级 session_service_config.persona_id` → `conversation.persona_id` → 全局默认人格。
所以「私聊人格1 / 群A 人格2 / 群B 人格3」会长期共存。

因此中间加一层映射：

```
persona（人格，外壳） --role_personas--> role（角色，好感度主体）
```

- `affinities(role_id, user_id)` 唯一；
- 新人格第一次出现时**自动建 1:1 角色**，行为上等价「按人格隔离」；
- 控制台可把多个人格归并到同一角色，之后共享一份分数；
- 事件仍记录 `persona_id`，因此「这份分数由哪个人格挣来」永远可查。

归并策略：**取最高**（不是相加、不是平均）。理由：相加会凭空造高分，平均会惩罚只在单一场景活跃的人，
取最高是「这段关系的最好证据」，与迁移自我学习旧分数时的策略一致。

## 3. 群维度：不分裂分数

群视图 = 「该群成员的全局分数排行」+「该群对分数的贡献」。
事件带 `session_id / group_id / is_group`，因此可以算「本群累计 +128，占 TA 总分 21%」。
**不**按群各存一份分数（那会与「统一成一个好感度」直接冲突）。

## 4. 三层时间模型

| 层 | 针对对象 | 驱动 | 存什么 | 怎么算 |
| --- | --- | --- | --- | --- |
| 关系层 | 某个人 | 互动事件 | 分数 + `last_settled_at` | 读写时惰性结算闲置衰减 |
| 情绪层 | 角色自己 | 事件 + 半衰期 | 基准四轴 + `updated_at` | 读时投影，不写库（v0.5.0 已实现） |
| 状态层 | 角色自己 | 世界时钟 | 锚点（睡眠/工作量） | **明确不做**（2026-11-11 决策：离开日程/作息接入就没有意义，不做随机数） |

**闲置衰减**（关系层，唯一口径）：连续 3 天无有效互动不动，第 4–7 天每天 −2，第 8–14 天每天 −5，
第 15 天起每天 −8。惰性结算：读或写时按 `last_settled_at` 补算并回写，不依赖定时任务。

#### 认识时间（first_seen_at）多渠道口径

「认识 N 天」= now − `first_seen_at`。`first_seen_at` 按「能证明的最早一刻」取值，渠道与时机：

| 渠道 | 时机 | 说明 |
| --- | --- | --- |
| 本插件首次事件 | 自动 | 新用户建档时 `first_seen_at = now`，天然准确 |
| 老库迁移 | 导入/回填时 | 老库四张表（`user_affections.created_at` / `raw_messages` / `user_conversation_history` / `affection_interactions`）每人取**全部来源最早**；`created_at` 在好感度行被重建时会变新，不单独信它 |
| 群入群时间 | 控制台「同步群名与成员」 | `get_group_member_list` 的 `join_time`；认识时刻 = **max(用户入群, bot 入群)**，多群取最早；跨全部角色回填 |
| 人工指定 | 用户详情页 | 成为好友的时间、私聊首聊 OneBot 协议**拿不到**，人工兜底；允许任意方向 |

维护工具：`repair_first_seen` / `repair_first_seen_all` 只把时间往**早**修；
`set_first_seen` 是人工指定，允许任意方向但不许超过当前时间。两者都直接改 `affinities.first_seen_at`、
不写事件流水（first_seen 不是分数，不走 `apply_event`）。

## 5. 数值

- **分数无上限**，只有下限 0（存 REAL 便于衰减）。
- 档位按**绝对阈值**（分数无限，不能用比例划分）：陌生 0–99 / 眼熟 100–299 / 熟悉 300–599 /
  亲近 600–999 / 亲密 1000–1999 / 羁绊 2000+。
- 控制台的分数条显示「当前档位内的进度」，用相邻阈值做区间，不依赖任何上限。
- 每日正向增益上限、每日负向扣分上限各自独立（防刷分/防一次性打穿）。
  **上限只对核心计分（`source = "core"`）累计与夹紧**：`manual.*` / `import:*` 本身不受限
  （一次 −100 不会被夹成 −20），也不占当日额度——否则导入几百分会把当天聊天计分一口吃光。

## 6. 计分

事件驱动，不按「每条消息 +N」无脑加：

| 事件码 | 默认 | 说明 |
| --- | --- | --- |
| `chat.daily_first` | +2 | 每个角色×用户每天首次有效对话，`dedupe_key` 去重 |
| `chat.message` | +1 | 普通对话，受每日上限约束 |
| `chat.attention` | +2 | 被 @ / 唤醒 |
| `chat.praise` | +3 | 命中夸奖词（默认空=关闭，防误判） |
| `chat.negative` | −6 | 命中负向词，**负面优先**，该条不再给正向分 |
| `manual.*` | 任意 | 控制台/管理员手动调整，写 `operator` 与 `reason` |
| `import:*` | 任意 | 迁移导入，可整体撤销 |

一切变更都落 `events` 流水（`before`/`after`/`evidence`/`dedupe_key`），**不直接 UPDATE 分数**。

## 7. 注入

`on_llm_request` 追加固定 marker 包裹的短文本（默认 ≤140 字）：关系档位、分数、认识天数、最近互动间隔。
末尾固定一句「这是表达参考，不要播报分数，也不作为权限或事实依据」。
情绪层落地后在同一块内追加一行心情。

## 8. 对外契约

```python
star = context.get_registered_star("astrbot_plugin_moe_affinity")
api = getattr(star.star_cls, "api", None) if star and star.activated else None
if api and api.API_VERSION == "affinity.v1":
    snap = await api.get(role_id, user_id)
    snap = await api.add_event(role_id, user_id, source=..., code=..., delta=...)
```

取不到 / 版本不匹配 / `status="unavailable"` 时，调用方必须安全降级，不能把缺失当 0 分。

## 9. 控制台（v0.3.0 已实现）

hash 路由，筛选/分页/时间窗全部落在 URL 上（刷新不回首页）：

```
#/overview   #/users   #/users/:id   #/groups   #/groups/:id
#/rank       #/config  #/data        #/audit
```

前端 Vue3 + vue-router(hash) + Naive UI + ECharts，构建约束沿用 `moe_permission`：
`base:'./'`、单 chunk、`cssCodeSplit:false` + `cssInjectedByJs`、`assetsInlineLimit 300KB`、
一律走 `window.AstrBotPluginPage` 桥接、禁用 localStorage（sandbox iframe 无 same-origin）。


## 11. 与其他插件的关系

- 自我学习：关掉它的 `enable_affection_system` 与两个 mood 开关，保留学习功能；
  迁移读它的 `messages.db` → `user_affections`，按用户聚合成一条（**取最高分**），
  原始多群记录整条塞进 `evidence` 留档。
- 陪伴插件 7.x：没有对外写入口，只能单向读它的关系档案做文本补充；数值以本插件为准。
- 冲突检测：启动时扫描其它插件是否仍在注入好感度/情绪，在控制台给出提示（不做强制干预）。
